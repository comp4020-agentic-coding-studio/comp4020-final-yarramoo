| D-021 | 2026-10-13 | Supersedes D-018: Water touching Fire turns the fire cell into Steam (water stays); Fire ignites Wood (1 in 12 per tick per fire neighbour) and Seed/Stem/Flower (1 in 4); Fire touching fuel does not drift away; a dying Fire becomes Smoke 1 time in 3. | Plan 6.4 gives no numbers; these make wood burn through in a few seconds without instant flash fires. |
| D-022 | 2026-10-13 | Explosions are resolved after the cell pass in queue order, at most 256 per tick; the queue is scratch, not state. A gunpowder cell touching Fire or Lava is primed (`aux = 1`) and explodes on its next update; blast-caught gunpowder is primed and goes the next tick. Leftovers beyond the cap stay primed in the grid and go on later ticks. | Keeps per-tick cost bounded (256 x about 49 cells) and the chain visibly spreads over ticks; storing the "queued" bit in `aux` means a snapshot taken mid-chain restores correctly. |
| D-023 | 2026-10-13 | Blast carves every non-Bedrock cell within radius 4 to Empty, except the rim (distance beyond 3), where 1 in 3 cells becomes Fire. | Plan asks for rng-chosen Fire on the rim. |
| D-024 | 2026-10-13 | Seed `aux` counts germination progress (needs 60 increments; each tick increments with probability 1/2 if Water within 2 cells, else 1/6). Stem `aux` is `target<<4 \| height`; only the growing tip has non-zero aux, mature stems have 0. A blocked tip matures without a Flower. Seeds, Gunpowder and Sand sink through Water, Lava and light gases; Water and Lava displace Smoke and Steam by swap. | Keeps all plant state inside the existing two byte arrays so hashing and snapshots need no change. |
| D-025 | 2026-10-13 | `paintable` is everything except Bedrock (ids 0, 2-14). Input generator paints all ids (Bedrock is skipped by the sim) plus reactive pairs (gunpowder+fire, lava+water, dirt+seed, wood+fire, gunpowder+lava). | Bedrock is the world boundary; D2 needs the reactions to actually happen. |
| D-026 | 2026-10-13 | The client worker reads `mat`/`aux` through the wasm exports, captured by wrapping `WebAssembly.Instance` while `shared/sim.ts` loads, rather than editing `shared/sim.ts`. | `shared/` was out of scope for M1 and `loadSim` does not expose the exports; a later change should add `matView()`/`auxView()` to `Sim`. The views are read-only; no TypeScript writes sim memory. |
| D-027 | 2026-10-13 | Client steps at 60 Hz with a fixed accumulator, at most 4 steps per frame, dropping any backlog beyond one step. Paint inputs are queued in the worker and pushed immediately before the frame's first step. Player id 1 and seed 1 are used for the single-player sandbox. | Matches the brief; real player ids and seeds arrive with the server in M2. |
| D-028 | 2026-10-13 | Canvas is the 512x512 world only (no camera), scaled by the integer factor that fits, else fit-to-space. Render fallback: main thread WebGL2 fed by transferred copies of `mat` and `aux` from the worker. | M1 sandbox is one screen; the 480x270 game view is for M3. |
| D-029 | 2026-10-13 | Supersedes D-026: `shared/sim.ts` exposes read-only `matView()`/`auxView()`/`width()`/`height()`, and the worker uses them; the `WebAssembly.Instance` monkey-patch is gone. | Patching a global constructor is fragile and would also catch the server's verify-only instance later. The views are render-only, which invariant 9 already allows. |
| D-030 | 2026-10-13 | Ticks are numbered from 1; closed tick k is applied as "push its inputs, then step", so `sim.tick() == k` afterwards. WELCOME carries the last closed tick, which is the client's replay target. | Matches the sim's tick counter (starts at 0 after init) with no off-by-one between server log and client. |
| D-031 | 2026-10-13 | M2a keeps the full closed-tick log in server memory from tick 0 and replays all of it to every joiner; `World.join(peer, fromTick)` takes the start tick so snapshots can slot in. Joins get REJECT ("world log is full") past 200,000 ticks (~55 min of play time; ~1 MB of empty ticks). | Snapshots are the next slice; the cap bounds memory and join time until then. |
| D-032 | 2026-10-13 | Protocol v1: HELLO is `version u8, hash[32], token[32], world_id u32` (token unused until identity). INPUT carries the sim input minus its kind/player fields, which the server re-adds (`simInputBytes`), so a client cannot name another player. Join and Leave are never accepted from clients. TICK entries are `player u32, kind u8, len u16, payload`. WELCOME also carries the last closed tick. | Plan 7.2 left byte layouts open; this keeps the server blind to sim input layout beyond the Paint length check. |
| D-033 | 2026-10-13 | Rate limit is a fixed 1 s window of 40 inputs per connection; excess is dropped and counted (`stats.droppedRate`). Malformed frames close the socket; wrong-kind or wrong-length INPUT is dropped and counted. Max frame 256 bytes. The client coalesces drag strokes to one Paint segment per 33 ms (~30/s). | Under the cap in normal play; a long fast drag is coarser than local painting was, but remains continuous because segments chain from the last sent point. |
| D-034 | 2026-10-13 | Playout: hold when empty and rebuffer to J=2 before resuming; fast-forward during catch-up runs unthrottled in 12 ms slices per frame (render between). Reconnect discards the sim, builds a fresh instance and replays; backoff 0.5/1/2/4 s; a REJECT stops reconnecting. The player count is derived client-side from Join/Leave in the tick stream (UI only). | Simple and correct per the brief; REJECT must not loop. |
| D-035 | 2026-10-13 | The server starts a world clock only while players are connected; the 4 ms `setInterval` calls `advance()`, which closes every passed tick in order, and `stamp()` also advances first so an input is never filed into a tick the clock has already passed. | Late timers cannot skip ticks or misfile inputs. |
