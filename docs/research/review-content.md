## Should-fix
S1. Nothing guards the well shaft against liquid or gas put in after `place_structures` (gen.rs:380-394 order: structures, greenery, door yards, then oil, acid, gas, ice, coal, halls, repair).
A cave well opens into an existing cave (gen.rs:2162-2172). `try_pool` (gen.rs:1131) floods every Empty cell at or below the pool level connected to the seed, so an oil pool (shallow band, `place_oil` gen.rs:1243) or an ice-site water pool (`place_ice`, gen.rs:1363) in a basin whose rim is within 7 rows of the opening can fill the bottom of the shaft. The `bad` test (gen.rs:2165) only sees liquid present at placement time. `wells_open_to_a_reachable_cave_or_hold_water_on_solid` (tests/structures.rs) checks `floor..bottom` Empty on 48 worlds, so it passes today, but it neither checks the 4 extra rows the shaft clears into the cave (`last = bottom + 3`, gen.rs:2183) nor liquid or gas in the shaft. Probability looks low (opening is at most about `s0 + 120` rows at L, ice sites start at about row 290). Cheap fix is a post-pass (after `place_biome_halls`) that asserts or blanks liquid and gas in each cave well's shaft, or at least add the assertion to the test.

S2. Arena and lava-lake guards in `place_well` are dead code, and the test that claims to check them is vacuous.
`maxd = scale_u(h,120).max(12)` (gen.rs:2161) bounds the opening at about row `s0 + 120`, well above `deep_top` (800 at L, 243 at S) and the arena band (`cy - ry >= surface_y + 60`, in band >= deep_top), so `y >= sc.deep_top` and the `a.contains(xi + 3, y, ARENA_KEEP_OUT)` checks (gen.rs:2166, 2173) can never fire; `struct_site`'s arena check (gen.rs:2021) tests `base`, near the surface, with the same result. The checks are harmless but they check only column `xi + 3` at one row, so if `maxd` is ever raised the shaft (7 wide, 4 rows extra) could clip the keep-out ring. `structures_keep_out_of_the_spawn_columns_and_the_arena` only tests rows `top`, `floor`, `bottom` of each structure against the arena, which are all near the surface for houses and water wells, so the arena half cannot fail. Say so in the test comment, or drop the claim.

S3. `houses_can_be_walked_through_and_entered` and the fire test contain dead or vacuous parts.
`let _ = reach;` (the `box_reach` closure is never called), `let _ = sky;`, and `let _ = wide;` in the keep-out test are unused. The standing-spot and side-reachability assertions are real (the 5x10 box flood cannot enter through the roof because the gap removes only the top roof row, gen.rs:2111-2113, so inside reachability implies the door). The fire test (`fire_on_a_roof_is_bounded_and_sleep_invisible`) returns `None` for both runs when a world has no house or when the cell at `(x0 + 6, top + 1)` is not Wood, so `assert_eq!(a, b)` passes with `None == None`. Seeds (1,1), (1,2), (2,3) should be checked in `/tmp/cw1-fire.txt` to see at least one burned; add `assert!(any_ran)`.

## Nit
N1. Doorsill step. Floor row is `base` = the highest ground in the span plus 3 columns either side (gen.rs:2013), while outside ground can be up to 4 rows lower, so a door can sit a 4-row step above the outside ground (footing loop gen.rs:2087-2091). The reachability test uses a box flood with no step limit; check the avatar's step-up (client/avatar.ts) before claiming "entered". Not a sim issue.

N2. `dig` in the well removes `SAND | GUNPOWDER` (gen.rs:2184) but the `hit` scan treats `BRICK | WOOD` as solid (gen.rs:2162). A Brick or Wood cell (mine beam) in the shaft path would be left in the shaft. Then the test fails loudly, not silently, so low risk.

N3. The brief's `ENEMY_SPAWN_CLEAR` is not used; `SPAWN_CLEAR_COLS` (168) is stricter, as the doc comment says. Test imports `ENEMY_SPAWN_CLEAR` only for the dead `wide` counter.

N4. tests/structures.rs uses `std::collections::HashSet` (clippy `disallowed-types` is for `sim/`; the gate runs clippy on the lib only, per `.claude/skills/run-tests/SKILL.md:27`, so it passes, but a `--all-targets` clippy would flag it). Use `Vec<bool>` or `BTreeSet`.
